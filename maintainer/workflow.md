# 材料蒸馏、贡献与更新

## 固定输入

贡献单位是完整评分案例。提交与成绩对应的实际文稿，保留批注和修订；注明当前文件是原始提交、批阅副本还是事后改稿。后期改稿不能直接搭配原分数作为评分样本。

使用 [contribution-template.json](contribution-template.json)。文件路径相对私人材料包；成绩值、满分和范围分开记录。未知满分不默认填满分制。课程总评、单篇分、分项分及不同评分人的意见分别保存；不知道合成规则时不能自行平均。无分数的原件进入待补充区。

用 `python -X utf8 maintainer/check_contribution.py "<私人材料包中的清单.json>"` 检查材料路径、版本声明、成绩范围和授权。检查器只检查结构，不能代替对原件和评分真实性的核验；得到 `course_total_only` 或 `pending_grade_or_scope` 时不进入单篇成绩比较。

贡献者确认有权提供原件，并分别选择是否允许私人分析与公开抽象规则。个人身份与真实教师名只进入私人映射表。新教师追加稳定代号，禁止重排旧代号。重复姓名或拼音只作为待核对别名，不自动合并身份。

## 私人提取与来源核验

在仓库外准备独立私人目录，运行：

```powershell
python -X utf8 maintainer/extract_case.py --source "<私人材料目录>" --private-output "<独立私人提取目录>"
```

DOCX 提取正文、表格单元格文本、脚注、批注锚点与修订。PDF 提取逐页文本。提取器不执行文内代码或指令，不修改原件，不联网，禁止将证据输出到本公开仓库或与原件目录重叠的位置。

提取不是视觉核验。图像不自动 OCR，数学结构、表格布局及无文字 PDF 需要查看原件；缺失内容标为未核查。含修订的文件保留接受修订与修订前的文字视图及原始修订记录，不把接受后的文字自动当作获评分版本。

核对任务文档是否混入个人提纲、草稿或对话；按段落划分真实任务与非任务内容。批注作者别名只有经核对才能关联教师；其他批阅者单独保存。核对封面、目录和要求中的课程、教师、年份；冲突记录在私人案例和公开档案的局限中。

## 如何蒸馏偏好

将论文表现与对应得分放在中心，而不是照抄通用评分表。具体批阅用于说明哪些做法获肯定、哪些有问题。题目小分与明确约束独立保留；泛化的评价套话只作低权重背景。

每篇记录：任务目标、论点、材料、方法、论证链、组织、亮点、问题、对应评分、批阅及版本状态。然后在同课程、相近作业中比较。只有同一作者不同题目的分差，不足以识别某一特征的提分幅度；不同教师或不同课程的分数也不能直接排列成偏好强度。

每条规则必须回答：适用于哪里、观察到了什么、建议检查什么、怎样修改、哪些反例或限制仍存在。公开规则使用“明确要求／教师反馈／案例推断／一般写作建议”之一；私人来源账本记录文件哈希、段落或批注编号、关联案例与得分范围。

较好评分案例可以产生积极的候选策略，不必等到大量样本才提供帮助；但标注单篇、同作者或未独立验证的局限。高分不代表案例每个理论、数字和引用均正确。不能把题材、立场、复杂技术或引用教师作品本身推定为加分条件。

优先把局部规则放入课程对应作业。只有多门课程的适用证据支持时才提炼跨课程教师偏好；教师档案引用课程规则编号，避免拷贝第二套评分标准。未知教师评分偏好可空缺，但课程仍应提供有标签的实用建议。

## 公开数据接口与更新

[catalog.json](../skills/course-grade-guide/courses/catalog.json) 是课程、批次、教师与作业关系的唯一机器数据源。每门课程有稳定 `course_id` 和别名；`offerings` 包含稳定 `offering_id`、学年、学期、班级、教师代号列表和作业列表。未知学期或班级用 `null`，不能视为所有班级通用。多人授课保留多个代号；评分人未知时不能凭任课名单指定评分者。

课程 Markdown 是诊断规则正文的来源；索引用于阅读导航。教师 Markdown 仅保存有适用条件的综合判断并引用课程规则。新增批次后同步导航并运行校验。规则编号稳定，修改内容提高私人版本号，记录支持、修订、限制范围、新增或撤回的原因。旧学年规则保留，不能覆盖成最新版本。

贡献者撤回时，先停止使用对应私人案例，检查其支持的规则；没有其他依据的规则应删除或降级，并重新检查公开内容。发布后的 Git 历史需要单独处理，不能承诺其他人的副本可被追回。

## 发布检查

公开仓库不存原件、教师真名、个人得分、论文题目、原文摘录、批注作者或私人路径。不能把个人信息放进测试、日志、提交说明或打包文件。允许保留课程任务本身的分值、篇幅和文献数量。

维护者在仓库外维护 JSON 禁止词表，格式为 `{"tokens": [], "private_roots": []}`，填入真实姓名、别名、学号、联系方式、论文题目与私人路径。不要提交该文件。

```powershell
python -X utf8 maintainer/validate.py
python -X utf8 -m unittest discover -s maintainer/tests -v
python -X utf8 maintainer/release_check.py --denylist "<私人禁止词表.json>" --evidence-dir "<私人提取目录>"
```

检查器扫描工作区、已暂存内容及已有提交对象；匹配身份词、联系方式、个人成绩标记、私人路径、原件类型，以及与私人正文或批注重合的长片段。不会显示命中的敏感文字。禁止词和片段扫描不能检测所有改写或间接身份暴露，仍需人工逐文件审阅。没有私人词表时仅能做基础扫描，不视为完整发布检查。

GitHub 发布前核对贡献者允许公开的范围与规则来源，审核差异和提交说明；再由维护者执行公开发布。提取或测试过程不创建远程仓库、不自动提交或推送。

## 效果验证

general 层见 [全课程汇总分析](../skills/course-grade-guide/general/guide.md)。更新时检查新案例是否支持、限制或反驳既有 Gxx 方法，保留来源课程规则和任务类型；只在单门课出现的做法应如实注明，不能升级成全院共识。新增课程独立档案后，匹配成功优先使用该档案，general 只补证据空白。

小幅补分、纠正元信息或文字更新只检查受影响记录与发布差异，无需重新提取全部原件或运行全部测试；涉及匹配逻辑时，检查相应路由。不得将旧的全量验证记录标成新一轮运行结果。

合成场景测试检查匹配、作用范围、数据类型与隐私检测。agent 行为检查另用 [场景集](behavior-cases.json)，记录实际输入、输出和失败，不能把测试预期当成实际执行结果。

样本足够时按整篇论文留出，最好按贡献者或学年留出；同一论文的不同版本不能分到两侧。比较加载和不加载 skill 的评价，在具体定位、依据正确、建议可执行和误判方面盲评。未校准前保持历史分数预测关闭；不能因格式或合成测试通过就声称已提高真实成绩。
